# Implementation Map

- [Vulkan isometric RPG plan](./vulkan-isometric-rpg-plan.md) is the implementation sequence for the Windows C and Vulkan game.
- [Initial implementation prompt](../prompts/0002-prompt-implement-vulkan-step-1.md) defines the completed Step 1 scope.
- [Step 2 implementation prompt](../prompts/0003-prompt-implement-vulkan-step-2.md) defines the native application foundation scope.
- The `game/` project owns the executable and its foundation tests.
  - [CMake configuration](../../game/CMakeLists.txt) defines the C project, discovers Vulkan, creates the `game` target, and enables warning-as-error Debug and Release builds.
  - [C entry point](../../game/src/main.c) owns executable startup, shutdown, and the consistent application error path.
  - [Application state](../../game/src/app.h) and [application loop logic](../../game/src/app.c) own pause, close, restart, fixed-update timing, variable-frame bookkeeping, and reset behavior.
  - [Platform boundary](../../game/src/platform_win32.c) owns the Win32 window, message handling, monotonic performance-counter timing, and native window cleanup.
  - [Foundation test](../../game/tests/foundation_test.c) verifies initialization, pause, fixed-step progress, activation, restart, and close state transitions.
  - [Build instructions](../../game/README.md) describe Debug and Release build commands.
- [Vulkan integration](../../game/src/vulkan.c) owns instance and validation setup, physical/logical device selection, graphics/presentation queues, the Win32 surface, surface format/present-mode selection, surface recreation, and Vulkan cleanup.
- [Vulkan interface](../../game/src/vulkan.h) exposes Vulkan initialization/shutdown/recreation and environment-independent format, present-mode, and queue-selection helpers.
- Debug builds enable `VK_LAYER_KHRONOS_validation` and `VK_EXT_debug_utils`; missing validation support is a hard initialization failure.
- The Win32 platform boundary creates the Vulkan state after native window creation and recreates the surface path on non-empty window resize; all Vulkan resources are destroyed before window cleanup.
- Step 4 owns the swap chain, one image view per swap-chain image, depth image and view, render pass, frame buffers, graphics command pool/buffers, in-flight fences/semaphores, clear-color submission, and presentation.
- Step 5 owns one documented vertex/uniform format, a perspective fixed-isometric view, one procedural cube, compiled vertex/fragment shader modules, one descriptor layout/pool and per-frame uniform buffers, a pipeline layout and graphics pipeline, and depth-tested cube drawing.
- Step 6 owns reusable procedural cube and plane meshes, indexed host-visible vertex/index buffers, scale-and-translation model matrices, per-object colors, and mesh draw commands.
- [Vulkan interface](../../game/src/vulkan.h) defines `VulkanMeshType`, `VulkanSceneObject`, mesh counts, and model-matrix helpers for environment-independent tests.
- [Vulkan integration](../../game/src/vulkan.c) creates 24 cube vertices with 36 indices and 4 plane vertices with 6 indices and uploads each mesh through a reusable host-visible buffer function.
- Mesh resources use stable device and memory ownership during a frame; swap-chain recreation destroys and recreates mesh buffers together with the pipeline resources, and shutdown destroys all remaining mesh resources.
- [CMake configuration](../../game/CMakeLists.txt) requires `glslc` and copies compiled cube shader modules beside the `game` executable through a post-build step.
- The frame loop waits for the current in-flight fence, acquires an image, records a depth-cleared render pass, binds the graphics pipeline and per-frame uniforms, binds each indexed mesh, pushes its model matrix and color, submits, and presents.
- Swap-chain recreation is triggered by resize or out-of-date/suboptimal acquisition/presentation; it recreates image views, depth resources, frame buffers, pipeline resources, commands, and synchronization while retaining the surface and logical device.
- [Vulkan test](../../game/tests/vulkan_test.c) checks queue, surface-format, present-mode, depth-format, in-flight-limit, mesh counts, level geometry helpers, model transforms, and perspective selection without requiring a live Vulkan device.
- Step 7 defines the fixed isometric camera, scene-center target, world-up, near/far planes, and level bounds in [Vulkan interface](../../game/src/vulkan.h) and [Vulkan integration](../../game/src/vulkan.c).
- The fixed view and aspect-dependent perspective are rebuilt and multiplied in projection-view order each frame; swap-chain recreation recalculates the aspect ratio while retaining the fixed camera.
- [Step 8 implementation prompt](../prompts/0009-prompt-implement-vulkan-step-8.md) defines the fixed-level scope.
- Step 8 owns an 8 by 8 fixed tile grid, 1-unit tile scale, procedural ground tiles, wall and obstacle collision states, a walkable spawn at tile `(1, 1)`, and a level-scene builder in [Vulkan interface](../../game/src/vulkan.h) and [Vulkan integration](../../game/src/vulkan.c).
- The level scene uses the existing plane and cube meshes: 64 individual ground planes plus procedural wall or obstacle cubes; environment-independent helpers provide tile validation, coordinate conversion, walkability, spawn validation, and level bounds.
- [Step 9 implementation prompt](../prompts/0010-prompt-implement-vulkan-step-9.md) defines keyboard input and fixed-step player movement scope.
- Step 9 owns held WASD/arrow-key state, normalized isometric-world movement, fixed-step direct speed, idle/moving state, eight facing directions, spawn/reset behavior, and axis-separated collision resolution in [application state and helpers](../../game/src/app.h) and [application loop logic](../../game/src/app.c).
- The Win32 boundary in [platform integration](../../game/src/platform_win32.c) maps held movement keys to `App`, wires the existing level walkability predicate to collision checks, and preserves P, R, and Escape events.
- [Vulkan integration](../../game/src/vulkan.c) appends a procedural humanoid-like player from existing cube meshes plus a colored facing marker to the level scene; player position and facing remain owned by `App`.
- Foundation tests cover idle/movement, direction mapping, all eight facing directions, boundaries, and collision resolution; Vulkan tests cover the procedural player scene helper.
- The rendering verification found and corrected an invalid Vulkan perspective matrix convention in [Vulkan integration](../../game/src/vulkan.c); the fixed camera now uses valid Vulkan clip depth and is covered by [Vulkan test](../../game/tests/vulkan_test.c).
- Live rendering verification and its observed pass/fail report are recorded in [Vulkan rendering verification](./vulkan-rendering-verification.md).
